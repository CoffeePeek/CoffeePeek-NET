# Импорт specialty-кофеен Минска

Решения из `/gsd:explore` (2026-08-15):

- **Цель:** наполнить приложение реальными specialty-кофейнями; без них продукт бесполезен.
- **Scope v1:** кофейни (не зёрна). Зёрна и прочее — позже.
- **География:** Минск. Цель ~200–250 specialty; кандидатов может быть до ~1000 (шум: автоматы, «просто кофе»).
- **Поток:** collector → **админ-очередь в CoffeePeek** (категория Kind, не да/нет) → в ленту все одобренные Kind.
- **Категории v1 (2026-08-15):** `Specialty` · `GoodCoffee` (хороший кофе, не specialty) · `Cafe` (еда + достойный кофе) · `ToGo` (с собой / сеть). Отказ = не в ленту. Specialty — один тип, не единственный пропуск в ленту.
- **Карточка очереди:** координаты недостаточны. Куратор смотрит Instagram и фото Яндекса — эти ссылки (и превью сайта) должны быть на карточке. OSM почти без фото. Не разбирать все 1500: сначала ~380 с кофе-сигналом.
- **Отбор:** сначала ручной разбор малой выборки → по паттернам — автофильтр.
- **Источник кандидатов:** **OSM + публичные/ручные specialty-подборки**. Яндекс — только **Geocoder** (координаты). Не парсить HTML-карточки Яндекса; Places/Organization Search не использовать для хранения без data-storage лицензии (basic ToS запрещает persist org data).
- **Уже в коде:** Geocoder-модели в `CoffeePeek.Moderation.Infrastructure/External/Yandex/`; модерация шопов — естественное место для очереди импорта.
